## 一次都不卡的电话

这一版几乎全花在一件事上：**让她说话不卡**。

起因是一句很普通的抱怨 —— 「主要问题是声音卡顿，听感很不好，qq 单独发的语音就还行」。
那句「QQ 单发的语音就还行」是钥匙：同一个声音、同一个模型，差别只在**管道**。
QQ 是整段合成完再播，我们是边合成边播。

查了整整一晚上，错了两回，最后分三层量清楚了：

| 层 | 怎么量 | 结果 |
|---|---|---|
| 合成出来的波形有没有洞 | 直接拉 PCM，扫内部静音段 | 有，但那是**模型自己在标点处停 0.35~0.88 秒** |
| 播放端会不会断 | 每 2ms 读一次声卡的「还剩多少」，归零就是没东西可放 | 32k / 44.1k / 48k × 47ms / 120ms 缓冲，**中途 0 次** |
| 音频是不是还在路上 | 合成一秒的话要 0.65 秒以上 | 是。**边合成边播，迟早有个瞬间没得放** |

所以改了三处，缺一条都不成立：

- **整段收齐再播**。跟 QQ 发语音同一个形状。代价是开口晚一点（一句三秒的话多等一秒多）。
- **整段一次交给模型**：`batch_size` 4 + `parallel_infer`，不再一句一次调用。
  合成速度从 1.17 倍实时变成 **0.65 倍**，攒齐时间砍掉约三分之一。
- **把标点处的白压短**：只动没有声音的样点，句号留 160ms、逗号留 80ms，一个有声采样都不剪。
  最长停顿 880ms → 160ms。

外加两处保险：声卡那头留 120ms 缓冲；接缝做 5ms 淡入淡出（这样缓冲万一空了，是一声「淡」而不是一声「啪」）。

## 她自己的声音

接进了本地的 **GPT-SoVITS**：克隆你自己的音色，跑在显卡上，约 1.3G 显存，免费、不联网。
四个后端现在都在设置窗口里挑，挑之前能**先听一句**：

- `piper` 本地 ONNX · 免费离线 · 0 显存 · 播报腔
- `sovits` 本地 GPT-SoVITS · **克隆音色** · 约 1.3G 显存
- `cloud` 硅基流动 CosyVoice2 · 更自然 · 按量计费
- `openai` gpt-4o-mini-tts · 最自然、能听语气指令 · **本机没 key，未实测**

## 通话窗

- **8.3 帧 → 25 帧**。原来的重画间隔是 120ms，眼睛看得出来在跳；现在 40ms，
  呼吸的相位按帧数折算过（不会快三倍），底下那排电平条改成滑过去而不是一跳一跳。
- 画图对象全部缓存，一帧一个都不新建 —— 所以帧率翻三倍也没有把 CPU 吃满。
- **通话时动态壁纸自动退场**，挂断自动还回来（那才是「一开电话整机卡」的真凶：
  壁纸在核显上解视频把画面管线压满了）。
- 被强杀的电话不会再把壁纸和会话卡住：下次开窗先 `reap` 一遍旧记号。

## 一些修好的小谎

- 设置里的「多静算你说完」「一句最多几个字」**以前改了不生效**（引擎根本没读）。现在真读了。
- 云端 TTS 的「音色 / 语速 / 模型」以前是写死的常量 —— 界面上改了也不变。现在读同一份配置。
- 通话窗如果显示「她在说」，那她**真的在说**（以前合成阶段也会显示成说话）。

## 几个踩过的坑（写进 `docs/PITFALLS.md` 第 15 条）

- 别用 loopback 录音去数「咔哒」：录音自己在静音之后会插一个假尖峰，每次都在同一处，会被它骗。
- 想测播放有没有断，就测**交给声卡的那一段**，或者直接问声卡还剩多少。
- 别改回「拿到一块就 sink 一块」—— 那不是优化，那正是卡顿本身。
